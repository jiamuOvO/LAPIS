# LAPIS v4 动态受理实施与验收

## 当前状态

动态受理已在开发分支 `codex/intake-v3-development` 实现。核心提交 `9d4c231bf80b2cbbeaa0c4e8cf6fdb0505314299`；过期选择保护提交 `b11c39220cd09f1f63ea86980282cf5d5545a924`。沿用现有 Conda、Instructor、LangGraph 和 PostgreSQL，没有新增依赖、服务或数据库迁移。

本轮只验证软件受理和合成对话，没有提交真实材料计算，也没有形成科研结论。全部自动写库验收使用 `LAPIS_TEST_PG=1`、`LAPIS_DB_NAME=lapis_test`；未写入正式任务库。

## 实施内容

- 八个研究字段、来源、状态、草稿版本、确认和执行门槛由确定性代码控制；抽取与提案响应禁止未知键和错误类型。
- 推荐内容由模型动态生成；本地目录仅作为可选公开参考上下文，未覆盖的材料和缺失目录文件不阻止生成提案。
- `lapis_proposals.py` 定义固定提案结构：字段补充、理由、假设、限制、待澄清项和给定来源 ID。模型新提案统一 `suggestion_origin=model`、`evidence_status=unverified`。
- 选择只采用研究意图。没有文献的完整提案也可进入规约确认；既有资料不会把整项提案升级为已验证。未知条件仍可交研究设计确定，但不能形成执行许可。
- 生成记录包含模型、提示词哈希、操作 ID；请求引用提案摘要与快照哈希，完整提案保存在原操作的 `intake_operations.result`。
- 用户硬约束与原始目标不会被选项静默删除；材料／场景变化触发旧条件重审。混合选择、修改和撤回继续分别处理。
- 抽取或生成失败时整轮回滚；既有操作重放不重复调用模型或写入轮次。错误来源 ID、URL／DOI、伪造核验状态、过期选择均有拒绝路径。
- v4／`intake-rules-4.0` 为当前契约。旧 v1/v2/v3 请求版本保持可读，不重写历史请求；进入当前设计前重新核对。修改撤销有效请求指针。
- CLI 展示提案来源类别、假设、限制和待澄清项；`ready_for_design` 只允许研究设计，方法、模型、参数与科研审批仍是独立门槛。

## 当前边界与后续条件

模型提案可能在适用性和常识判断上出错。结构校验、给定来源 ID 与链接检查只能限制一部分错误，不能证明自由文本中的科学事实正确；未经核查的提案始终由研究人员审查。文献核查、真实适配器、质量检查、观察值和证据报告仍需独立实现与验收。

推荐通常增加一次模型调用，费用和耗时高于原静态目录。Instructor 每次调用至多两次尝试；关闭 SDK 自动重试。失败仍可由用户复用原操作 ID 明确重试。当前没有身份认证的审核人字符串不能作为真实高成本任务的可信授权。

## 启动与复现

现有本机环境直接重启聊天即可；数据库已应用迁移 005 时无需新迁移：

```powershell
cd F:\LAPIS
& .\scripts\start_pg.ps1
Remove-Item Env:LAPIS_DB_NAME -ErrorAction SilentlyContinue
Remove-Item Env:LAPIS_TEST_PG -ErrorAction SilentlyContinue
& .\.conda-lapis\python.exe -X utf8 .\lapis.py chat
```

隔离回归及测试替身：

```powershell
$env:LAPIS_TEST_PG='1'
$env:LAPIS_DB_NAME='lapis_test'
& .\.conda-lapis\python.exe -X utf8 -m unittest discover -v
& .\.conda-lapis\python.exe -X utf8 .\scripts\verify_intake_v4.py --mode mock --output .\reports\local-v4-mock.jsonl
```

`--mode real` 会发送合成对话、提示词和公开参考上下文，需要相应授权及 API 配置。旧 `verify_intake_v3.py` 已加契约检查，避免在当前代码上误称复现旧版验收。
